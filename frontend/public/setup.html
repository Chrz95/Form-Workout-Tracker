FORM / YOUR PERSONAL STUDIO

Your training, saved on your terms.

The private frontend preview includes the exercise library, live workout mode, rest timers and editable workout drafts. Custom exercises, persistent workout lists and training sessions use the supplied Express server with PostgreSQL.

Run the complete app with Docker

Download the latest source and run sh scripts/docker-up.sh from its root on Linux, macOS or WSL. Alternatively, use pnpm docker:init then pnpm docker:up. Open http://localhost:8080; saved training connects automatically through the local server proxy. Docker runs the frontend, Express API and PostgreSQL on port 5433 with persistent volume workout_data. See docs/DOCKER.md for direct Compose, Windows and remote hosting instructions.

Run locally without Docker

Start your installed PostgreSQL service and set its connection string in DATABASE_URL in the root .env. Run pnpm db:setup:local, then pnpm dev for development or pnpm start:local for the built app at http://localhost:8080. Both local modes connect automatically; legacy local API URLs also work. Credentials stay server-side.

1. Start the supplied server

Use Node 24.19.0, pnpm 11.25.0 and PostgreSQL 17. Copy .env.example to a private .env, choose a random API_ACCESS_TOKEN, and set the exact frontend origin. Leave VITE_API_BASE_URL blank for automatic local development connection.

pnpm install
pnpm db:setup:local
pnpm dev

2. Deploy the API for remote access

Build with pnpm build, run migrations as a separate release step, and start the Node API with pnpm start. Set production database credentials and the access token through deployment secrets. Expose the API through HTTPS and allow this frontend origin in CORS_ALLOWED_ORIGINS.

For release 2.4, apply all committed migrations and rerun pnpm db:seed to load the expanded public catalog. Apply migration 0003 for calendar plans and unique exercise-name keys, then reseed canonical and retired references. Custom exercises use the existing PostgreSQL reference table. Local PostgreSQL listens on port 5433 and stores its data in the Docker volume workout_data. The app verifies server capabilities and enables custom exercises, calendar plans and CSV import only when advertised. Release 2.4 adds reviewed atomic CSV import without a new migration; apply existing release 2.3 migrations and seed data first.

3. Connect a separately hosted API

Return to the studio, choose Connect workout API, and enter the full versioned HTTPS URL, such as https://your-server.example/api/v1, plus your private token. Connection loads saved lists and journal history before enabling synced use.

Credentials stay in this tab’s memory. All workout writes go through the API into PostgreSQL. Reconnect after refreshing. This server is for one owner; it does not implement shared multi-user accounts.
